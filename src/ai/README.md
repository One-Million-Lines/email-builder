# AI Assistant Module

A chat-driven editing layer that is part of the **core** email builder. It is
**disabled by default**: when enabled (and a backend is configured), an **AI**
tab appears at the top of the left sidebar; users describe the email they want in
plain language and the assistant builds and edits it change-by-change.

This module is the **client half**. The **server half** (model access, product
resolution) is the panel AI backend (`POST /ai/email/generate`, `/ai/email/products`,
`/ai/email/capabilities`, `/ai/email/mcp`). A reference Flask implementation also
lives in [`../../backend`](../../backend).

---

## Design principles

- **AI edits JSON, not HTML.** The model produces structured `AIAction`s /
  documents; the table-based HTML is always generated by the deterministic
  renderer. This keeps output email-safe.
- **Output is always valid & visible.** The client sends the full *capability
  surface* (modules + concrete samples, element fields, themes, settings, merge
  tags, special links, recommendation algorithms, product feeds). The backend
  only picks real module `type`s and assembles from those samples.
- **Real products, not placeholders.** Product grids are filled from named
  *product feeds* resolved server-side (top purchased, most viewed, …).
- **Untrusted by default.** Every response is validated with `documentSchema`
  and has fresh ids generated before it touches the store (`applyAIResponse`).
- **Core, but opt-in.** No `ai.enabled` → no AI tab, zero overhead.
- **MCP-ready.** The same backend can be driven by other agents via the tools in
  `mcp.ts` (`AI_MCP_TOOLS`, `buildMcpManifest`).

## Enabling AI

### First-class config (recommended)

```tsx
import { EmailBuilder } from "@one-million-lines/email-builder";

<EmailBuilder
  ai={{
    enabled: true,
    endpoint: "http://localhost:3001/ai/email/generate",
    // Optional: override the advertised product feeds.
    // productFeeds: [{ id: "top_purchased", name: "Top purchased", description: "…" }],
  }}
/>;
```

### As a plugin (legacy, still supported)

```ts
import { registerPlugin, aiAssistantPlugin } from "@one-million-lines/email-builder";

registerPlugin(aiAssistantPlugin({ endpoint: "http://localhost:3001/ai/email/generate" }));
```

### Custom provider (bring your own model logic)

Implement the `AIProvider` interface and pass it in:

```ts
import { EmailBuilder, type AIProvider } from "@one-million-lines/email-builder";

const provider: AIProvider = {
  async generate(req) {
    // req: { task, instruction?, document?, context?: { catalog, capabilities } }
    // return { actions?, document?, text? }
    return { actions: [] };
  },
};

<EmailBuilder ai={{ enabled: true, provider }} />;
```

For the standalone dev app, set `VITE_AI_ENDPOINT` in a root `.env` to enable the
panel automatically.

## Data flow

```
user prompt
   │
   ├─ buildCatalog()            → module catalog (with samples)
   ├─ buildCapabilities()       → full editor surface (elements, themes, settings,
   │                              merge tags, special links, recommendations, feeds)
   ▼
AIProvider.generate(AIRequest)  → HTTP POST to backend  → model / heuristic
   │                              (product feeds resolved to real products)
   ▼
AIResponse { actions | document | text }
   │
   ├─ applyAIResponse()         → validate (Zod) + regenerate ids + apply reducer
   │
   ▼
useEmailStore.applyDoc()        → canvas + HTML update
```

## Public API

| Export                 | Purpose                                                    |
|------------------------|------------------------------------------------------------|
| `aiAssistantPlugin`    | Register an HTTP-backed provider as a plugin.              |
| `createHttpAIProvider` | Build an `AIProvider` from an endpoint (used internally).  |
| `buildCatalog`         | Build the module catalog sent to the backend.             |
| `buildCapabilities`    | Build the full capability surface sent to the backend.    |
| `DEFAULT_PRODUCT_FEEDS`| Built-in product feeds (top purchased, most viewed, …).   |
| `setProductFeeds` / `getProductFeeds` | Configure / read advertised feeds.         |
| `AI_MCP_TOOLS` / `buildMcpManifest` | MCP tool contract + manifest.                |
| `applyAIResponse`      | Validate + apply an `AIResponse` to a document.           |
| `AIChatPanel`          | The chat UI (rendered inside the left sidebar).           |
| `useAIAvailable`       | Reactive hook: is a provider configured?                  |
| `mockAIProvider`       | Deterministic provider for tests/demos.                   |

Types: `AIProvider`, `AIRequest`, `AITask`, `AIResponse`, `AIAction`,
`HttpAIProviderOptions`, `CatalogEntry`, `Capabilities`, `ProductFeed`, `McpTool`,
`McpManifest`, `EmailBuilderAIConfig`, `ApplyResult`.

---

## Request/response contract

- **Request** (`AIRequest`): `{ task, instruction?, document?, context: { catalog, capabilities } }`.
- **Response** (`AIResponse`): `{ actions? } | { document? } | { text? }`.

`AIAction` variants (`src/core/aiActions.ts`): `insert_module`, `delete_module`,
`update_module`, `move_module`, `duplicate_module`, `update_element`,
`update_meta`, `update_settings`, `apply_theme`, `set_recommendations`.
